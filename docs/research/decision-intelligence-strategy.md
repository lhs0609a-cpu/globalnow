# Globalnow 의사결정 도구 재설계

## 제품 정의

Globalnow의 중심 고객은 해외 시장과 거래하는 사업자, 여러 지역의 조직과 자본을 관리하는 CEO, 국가·산업·기업 변화에 노출된 투자자다. 이들이 해결하려는 일은 뉴스를 많이 읽는 것이 아니라 세계의 변화 중 자신의 사업과 자본에 관련된 신호를 발견하고, 판단에 필요한 근거를 빠르게 확인하는 것이다. 성공적인 첫 화면은 세계의 변화, 관심 범위, 검토해야 할 상황을 연결해야 한다.

제품의 핵심 과업은 세계 현황 파악 → 관심 지역·산업·기업과의 관련성 확인 → 원문과 데이터 상태 검토 → 확인 과제 정리 → 브리프·저장 근거 재사용이다. 세계 지도는 장식이나 접어두는 부가 기능이 아니라 이 과업의 공간적 탐색 도구다. 다만 지도가 실제보다 정밀한 정보와 확실성을 암시하면 의사결정의 품질을 오히려 떨어뜨린다.

일반 뉴스 사이트는 편집된 기사 소비에 강점이 있다. Globalnow가 추가해야 할 가치는 기사와 지역, 산업, 기업, 시장, 검토 과제 사이의 연결이다. 이 차이는 메뉴 수나 실시간처럼 보이는 애니메이션보다 일관된 근거와 명확한 데이터 계약에서 생긴다. 전문 도구 수준의 방향성과 전문 데이터 서비스 수준의 실제 운영 능력은 구분해서 평가해야 한다.

## 전문 정보 도구에서 확인한 설계 근거

LSEG Workspace는 데이터·뉴스·분석을 연결하고 업무 맥락에 맞게 탐색하는 제품 구성을 설명한다. 이는 경제 기사를 많이 제공하는 것만으로 전문 사용자의 요구를 충족하기 어렵다는 설계 판단을 뒷받침한다. Globalnow에는 세계 현황에서 관심 대상과 근거 검토로 이어지는 일관된 흐름을 적용한다. LSEG의 콘텐츠 범위나 상업적 성과를 Globalnow가 보유했다는 뜻은 아니다. [LSEG Workspace](https://www.lseg.com/en/data-analytics/products/workspace)

LSEG의 뉴스 개발 문서는 키워드·코드·종목 식별자를 통한 검색과 주제별 주요 뉴스 탐색을 구체적으로 다룬다. Globalnow의 검색도 전체 기사 검색과 관심 기업·품목 키워드 모니터를 함께 제공해야 한다. 짧은 영문 종목 코드가 일반 단어의 일부에 우연히 포함됐다는 이유로 매칭되지 않도록 경계를 검사할 필요가 있다. [LSEG Data Guide, Chapter 12 — News](https://developers.lseg.com/content/dam/devportal/en_us/product-docs/lseg-data-guide/chapter12/)

Bloomberg의 NSTM 연구는 질의에 맞는 뉴스 개요 구성에서 주요 정보 추출과 중복·잡음 처리 문제를 다룬다. Globalnow에는 동일 제목의 기사 묶기를 우선 적용했다. 이는 사건 단위 의미 군집화나 독립 출처 검증을 구현했다는 주장이 아니다. 같은 통신사 기사를 재배포한 여러 사이트도 독립된 확증으로 세지 않아야 한다. [NSTM: Real-Time Query-Driven News Overview Composition at Bloomberg](https://arxiv.org/abs/2006.01117)

IMF PortWatch의 공개 설명은 항만·해상 운송의 관측 자료와 교역 차질, 공급망 파급을 연결한다. 이 사례는 전문 상황판의 차별점이 지도 자체가 아니라 위치에 연결된 관측값과 설명 가능한 관계임을 보여준다. Globalnow의 현재 기사 언급 지도는 이러한 실측 물류 데이터와 동일하지 않다. PortWatch는 공식 확인 경로로 제공하며, 통합 수치나 물류 위험 점수를 표시하지 않는다. [IMF, Climate Change is Disrupting Global Trade](https://www.imf.org/en/Blogs/Articles/2023/11/15/climate-change-is-disrupting-global-trade)

미 연준의 공식 FOMC 페이지는 회의 일정, 성명, 의사록, 경제 전망 자료를 연결한다. 전문 일정은 예상 이벤트 제목만 보여주는 것보다 공식 발표와 재확인 경로를 제공해야 한다. 현재 구현은 확인한 2026년 하반기 회의 날짜와 공식 링크를 제공하고 확인 날짜 및 자동 동기화 여부를 표시한다. [Federal Reserve, Meeting calendars and information](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm)

SEC EDGAR의 공시 검색은 뉴스 해석에서 공식 기업 근거로 이동하는 확인 경로다. 기사와 자동 분류를 보는 화면에 공식 원문을 연결하는 것이 필요하다. 공시의 존재만으로 거래의 경제적 의미나 투자 성과를 확정할 수 없으므로, 신호의 분류와 실제 공시 내용을 구분한다. [SEC, EDGAR Full Text Search](https://www.sec.gov/edgar/search/)

종료된 기능의 기존 경로는 상황판 또는 설정으로 이동한다. 종료 API는 HTTP 410을 반환하므로 기존 자동 호출이 성공한 것처럼 보이지 않는다. 과거 운영 데이터의 삭제는 기능 종료와 별개다. 기존 데이터베이스의 기록은 이 개편에서 삭제하지 않는다.

사용자 화면에서 제외한 기능이 백그라운드에서 계속 실행되지 않도록 유머·커뮤니티 트렌드의 예약 수집 워크플로도 제거했다. 이전 형식 브리프와 이를 발송하던 예약 워크플로는 새 의사결정 브리프와 데이터 계약이 달라 자동 실행을 중단했다. 수동 실행기의 기본 작업은 RSS·시장 수집으로 한정하며, 기존 형식 생성·선택적 리서치·발송 명령은 운영자가 명시적으로 실행하는 별도 경로로 남긴다.

## 세계 상황판의 정보 구조

상단은 제품 목적과 개인 모니터 설정, 브리프 내보내기를 제공한다. 긴 마케팅 문구로 첫 화면을 점유하지 않는다. 그 아래 시장 스냅샷은 주요 지수와 환율의 값, 변화율, 조회 시각, 데이터 상태를 함께 표시한다. 색으로만 상승·하락을 전달하지 않고 부호를 함께 사용한다.

상황 필터는 전체 상황과 내 모니터, 기간, 지역, 주제로 구성한다. 필터는 URL에 반영되어 새로고침·공유·뒤로가기에서 복원된다. 내 모니터의 관심 지역·주제·키워드는 이 브라우저의 저장 공간에 보관된다. URL만 공유하면 상대방의 관심 설정까지 전달되는 것은 아니므로 업무 문서 공유에는 내보낸 브리프를 사용한다.

요약 숫자는 해당 범위의 상황 수, 우선 확인 키워드가 감지된 상황 수, 언급 지역 수, 관심 범위 일치 수다. 숫자의 단위와 분모가 다른 지표를 하나의 종합 위험 점수로 합치지 않는다. 지역·주제가 여러 개인 기사는 여러 분류에 포함될 수 있으므로 분류별 합계가 기사 수보다 커질 수 있다.

지도와 우선 확인 목록은 같은 필터 범위의 자료를 사용한다. 지도 색상은 분류된 기사 유무를 나타내며 위험의 높낮이를 나타내지 않는다. 회색 국가에는 보도가 없거나 현재 분류 사전에 포함되지 않은 상태가 포함된다. 모든 사용자에게 같은 탐색이 가능하도록 지도 아래의 지역 버튼과 지역 선택 메뉴를 함께 제공한다.

상황 스트림은 시간, 분류, 제목, 출처, 원문, 저장, 근거 검토를 짧은 행으로 묶는다. 이미지 중심 기사 카드와 달리 업무 중 빠르게 훑고 비교하는 목적에 맞춘다. 더 깊은 읽기는 상세 대화상자와 원문으로 이어진다. 모바일에서는 같은 정보를 세로로 재배치하고 가로 넘침을 방지한다.

## 분류와 우선순위의 데이터 계약

입력은 수집 뉴스의 제목, 한국어 제목, 요약, 한국어 요약, 태그다. 원문 전체를 검증한 사실 데이터가 아니다. 기사 출처는 매체명과 원문 URL로 유지하며, 지역 분류에는 매체 소재지를 사용하지 않는다. 기사가 여러 나라를 언급하면 여러 지역으로 분류된다.

현재 지역 사전은 36개 주요 국가·지역을 대상으로 한다. 영어는 단어 경계를 확인하고 한국어는 국가명 일부가 다른 단어에 포함되는 오인식을 줄이는 규칙을 적용한다. 인도네시아를 인도로 세는 문제, 일반 문장 안의 짧은 영문 문자열을 국가·기술 약어로 인식하는 문제를 검증 항목으로 둔다. 지리 분류의 정확도가 임의의 모든 기사에서 보장되는 것은 아니다.

사업 관련 주제는 지정학·안보, 금리·거시경제, 무역·공급망, 에너지·자원, 기술·산업, 정책·규제다. 해당 키워드가 없더라도 국제·경제·기술·정치·리스크 카테고리 기사는 일반 동향으로 남을 수 있다. 스포츠·문화 등은 사업 관련 키워드가 없는 한 상황판에서 제외된다. 전체 기사 검색에서는 원래 기사를 계속 탐색할 수 있다.

우선 확인은 제재·봉쇄·침공·채무불이행·가동 중단 등 규칙에 맞는 기사를 먼저 배치하고, 그 안에서는 게시 시각을 사용한다. 이는 사건의 발생 확률이나 회사별 예상 손실 추정이 아니다. 상세 화면에 어떤 분류와 규칙이 표시의 근거인지 공개한다. 고급 사건 중요도 모델을 도입하려면 사람의 판정 데이터와 오탐·누락 평가가 필요하다.

동일 URL은 중복 제거하고, 정규화된 동일 제목의 기사는 묶어 원문 근거를 보존한다. 비슷한 사건의 서로 다른 제목을 자동으로 같은 사건이라고 단정하지 않는다. 별도 사건을 잘못 합치는 비용이 전문 정보 도구에서는 크기 때문이다. 독립 출처 수, 상충하는 주장, 최초 보도와 업데이트를 관리하는 사건 객체는 다음 단계의 데이터 모델이다.

기간 필터는 게시 시각을 기준으로 24시간·72시간·7일을 제공한다. 날짜가 유효하지 않은 자료는 날짜 미확인 건수에 포함하고 기간 목록에서 제외한다. 조회 시각은 최신 수집이 모두 성공했다는 증거가 아니다. 저장 자료와 샘플 전환도 화면과 내보낸 문서에 표시한다.

## 개인 모니터와 검토 과제

사업자는 매출 지역, 생산·물류 거점, 핵심 공급자와 투입 품목을 관심 설정의 출발점으로 삼을 수 있다. 투자자는 보유 기업, 섹터, 통화·지역 노출에서 시작할 수 있다. 현재 모니터는 선택한 지역·주제·키워드 중 하나라도 일치하면 포함하는 방식이다. 실제 매출 비중이나 공급망 거래 관계를 알고 계산하는 노출 모델은 아니다.

상세 화면은 보도 요약, 게시 시각, 자동 분류 지역, 매체 소재지, 표시 이유, 원문 근거를 함께 제공한다. 사업·투자 검토 항목은 주제별 질문으로 표시한다. 무역이면 적용 품목·시행일·물류 대안, 거시면 차입 만기·환 노출·수요 가정처럼 확인할 대상을 제시한다. 이 질문을 해당 기사에서 확정된 영향이나 AI의 매매 추천처럼 표현하지 않는다.

모니터 저장 실패는 화면에서 알려야 한다. 저장되지 않은 설정이 적용된 것처럼 보여 다음 방문에서 사라지는 경험은 업무 도구의 신뢰를 훼손한다. 현재 구현은 저장 공간 오류를 숨기지 않고, 기사 저장과 관심 설정의 저장 위치를 설명한다. 회사 계정 간 공유, 권한, 변경 이력, 공동 메모는 별도의 운영 설계가 필요하다.

## 브리프·산업 리서치·지역 비교

브리프는 현재 선택한 기간·지역·주제·모니터 범위를 문서에 기록한다. 제목과 요약만 복사하는 대신 출처 URL, 게시 시각, 데이터 모드, 확인 질문을 포함한다. 이후 문서를 읽는 사람이 자료의 범위와 한계를 다시 판단할 수 있어야 한다. 내보내기는 외부로 자동 발송하지 않으며 사용자의 로컬 파일 다운로드로 완료된다.

산업 리서치는 최근 7일의 수집 자료에서 반도체, AI·클라우드, 에너지·자원, 자동차·배터리, 금융, 무역·물류, 바이오·의료, 방산·안보를 탐색한다. 자료가 없으면 전망을 생성해 빈 공간을 채우지 않는다. 산업별 기사 수가 늘었다는 사실만으로 실적 개선이나 투자 기회를 확정하지 않는다. 공식 기업 자료와 통계, 가격 데이터에 대한 근거 연결이 추가로 필요하다.

지역 비교는 3개 국가·지역을 같은 기간과 주제 사전으로 나란히 확인한다. 기사의 발행 국가가 아닌 언급 지역으로 집계한다. 각 칼럼은 주제별 건수와 주요 원문을 제공하며, 자료가 없는 경우 이를 보도 공백으로 설명한다. 수집량이 많은 영어권 국가를 더 위험한 나라처럼 순위화하지 않는다.

## 평가 기준

핵심 지표는 방문 시간보다 첫 관련 상황 발견까지의 시간, 관련 근거 열기 비율, 모니터 설정 완료율, 브리프 재사용률, 오류 후 작업 복구율이다. 업무 도구에서 짧은 방문은 필요한 판단을 빠르게 마친 성공일 수도 있다. 일반적인 반송률을 단독 목표로 삼아 긴 체류를 유도하면 제품의 목적과 충돌할 수 있다.

분류 품질은 대표 언어·지역·산업의 기사를 사람이 검토한 자료로 평가해야 한다. 지역 오인식, 사건 묶기 오류, 중요한 사건의 누락, 샘플 혼입을 별도 결함으로 관리한다. 중요도 모델은 정확도 하나보다 우선 확인 목록의 오탐과 놓친 사건의 비용을 함께 봐야 한다. 평가 기준과 표본이 없는 종합 점수는 표시하지 않는다.

1만 명의 누적 사용자, 일일 사용자, 동시 활성 사용자는 서로 다른 부하 조건이다. 현재 구현의 제한된 스냅샷과 단일 프로세스 요청 공유를 1만 명 동시 접속 능력으로 환산하지 않는다. 수집 빈도·캐시 적중·인스턴스 수·외부 공급자 제한·오류 예산을 정한 뒤 실제 환경에서 부하를 측정해야 한다. 사용자 행동과 서버 관측 자료가 없으므로 이탈률 감소 수치는 산출하지 않는다.

## 검증 기록

구현 검증의 대상은 지리 분류, 중복 기사와 원문 보존, 날짜 범위, 관심 설정의 저장·복원, URL 필터와 뒤로가기, 근거 대화상자의 포커스 복귀, 범위별 브리프 다운로드, 오류 후 이전 자료 보존과 재시도, 국가 비교, 산업 필터, 종료된 경로, 반응형 화면과 자동 접근성이다. 브라우저 검사는 고정된 응답을 사용하므로 외부 데이터 공급자의 현재 가용성을 검증하는 시험은 아니다.

최종 프로덕션 빌드는 컴파일·TypeScript 검사와 56개 페이지 생성을 완료했다. 전체 ESLint 검사에서는 오류 0개와 기존 경고 3개가 확인됐으며, 마지막 수정 파일의 추가 검사도 통과했다. Playwright 브라우저 검증은 17개 모두 통과했다. 국가·주제·기간 필터와 브라우저 기록, 관심 설정 저장·복구, 근거 대화상자, 브리프 내보내기, 오류 복구, 지역 비교·산업 필터, 종료 경로와 기존 뉴스·저장 흐름을 포함한다.

상황판과 뉴스 화면은 320·390·768·1024·1440px에서 가로 넘침을 검사했다. 390px·1440px의 라이트·다크 테마에서 axe 자동 접근성 검사 위반은 0개였다. 데스크톱 다크 및 모바일 라이트 상황판 캡처를 직접 확인했고, 분류 대상 밖의 국가가 선택 색으로 표시되던 지도 오류도 수정 후 확인했다. 자동 검사는 전체 WCAG 준수 인증을 의미하지 않는다.

캐시 검사는 동시 100개 요청이 하나의 조회로 합쳐지는 동작, 만료·크기 제한·오류 재시도와 안정적인 RSS 식별자를 확인했다. 이는 단일 프로세스의 기능 검증이며 운영 부하 시험이 아니다. 운영 계정·조직 권한, 실측 분류 정확도, 실제 1만 동접 부하, 상용 데이터 라이선스는 로컬 검증 범위 밖이다.
